# 연결하기 — 이미지 제작 프롬프트 가이드

중학교 기술 수업용 게임형 웹앱  
**「연결하기 — 연결 기술 탐험대」**의 이미지 제작 규칙과 프롬프트 템플릿이다.

새로운 채팅에서 동일한 스타일의 이미지를 제작하려면 이 문서를 먼저 전달하고, 이후 각 이미지를 **한 장씩** 요청한다.

---

# 1. 새 채팅 첫 메시지용 마스터 프롬프트

```text
중학교 기술 수업용 게임형 웹앱
‘연결하기 — 연결 기술 탐험대’에 사용할 이미지를 제작하려고 한다.

앞으로 만드는 모든 이미지는 다음 공통 디자인 규칙을 반드시 따른다.

[대상]
- 중학교 1~3학년
- 기술 교과 수업
- 게임형 웹앱에 사용하는 교육 이미지
- 유아용 캐릭터가 아니라 중학생에게 적합한 디자인

[공통 스타일]
- 현대적인 기술 교과서형 벡터 일러스트
- 사실적이면서 핵심 구조가 쉽게 보이는 설명형 그림
- 매우 밝은 회청색 또는 흰색에 가까운 배경
- 일정하고 깨끗한 짙은 남색 윤곽선
- 하늘색, 민트색, 주황색, 노란색을 포인트 색상으로 사용
- 약간의 입체감과 부드러운 그림자
- 둥글고 친근하지만 지나치게 유아적이지 않은 형태
- 재료와 도구는 실제 형태와 작동 원리에 맞게 표현
- 카드나 버튼으로 축소해도 대상을 알아볼 수 있는 명확한 실루엣
- 이미지 바깥쪽에 충분한 여백 배치
- 모든 이미지에서 조명, 시점, 선 굵기와 색상을 통일

[교육 이미지의 표현 방식]
- 연결 전 재료
- 핵심 연결 과정
- 연결된 완성 상태
위 세 가지가 하나의 자연스러운 장면에서 이해되게 한다.

확대 단면을 사용할 경우:
- 중심 그림과 확대 그림의 부품 모양이 같아야 한다.
- 색상, 방향, 크기 비율과 부품 위치를 일치시킨다.
- 실제로 결합할 수 없는 구조를 만들지 않는다.
- 돌출부와 홈, 볼트와 구멍, 핀과 단자의 크기 및 위치를 정확히 맞춘다.

[금지 사항]
- 한 이미지에 서로 다른 여러 주제를 넣지 않는다.
- 여러 시안, 여러 패널, 격자와 콜라주로 만들지 않는다.
- 요청한 이미지 외의 다른 재료나 도구를 넣지 않는다.
- 사람과 손은 별도로 요청한 경우가 아니면 넣지 않는다.
- 상표, 회사 로고와 워터마크를 넣지 않는다.
- 위험한 부상, 피, 폭발과 과도한 불꽃을 넣지 않는다.
- 이미지 안에 한글, 영문, 숫자와 설명을 넣지 않는다.
- 제목과 설명은 웹앱의 HTML 텍스트로 표시한다.

[중요]
- 한 요청에서 이미지 한 장만 생성한다.
- 시안이나 변형 이미지를 여러 장 만들지 않는다.
- 요청하지 않은 대체 이미지를 만들지 않는다.
- 이미지 파일명으로 사용할 권장 이름을 답변에 함께 알려준다.
- 기술적으로 애매한 구조는 임의로 그리지 말고 먼저 실제 구조를 확인한다.
- 내가 참고 이미지를 첨부하면 참고 이미지의 기하 구조는 그대로 유지하고 색상과 그림 스타일만 변경한다.

이 규칙을 기억하고 이후 모든 이미지 제작에 동일하게 적용하라.
```

# 2. 핵심 제작 규칙

## 반드시 지킬 것

1. 한 요청에서는 이미지 한 장만 제작한다.
2. 한 이미지에는 주제 하나만 표현한다.
3. 이미지 내부에는 원칙적으로 글자를 넣지 않는다.
4. 제목과 설명은 웹앱의 HTML로 표시한다.
5. 실제로 결합 가능한 구조인지 확인한다.
6. 연결 전, 연결 과정, 연결 후 상태가 논리적으로 이어져야 한다.
7. 확대 단면과 중심 그림의 형상이 일치해야 한다.
8. 이미지 파일명을 답변에서 알려준다.

## 피해야 할 것

- 여러 이미지를 한꺼번에 요청하기
- 한 이미지에 여러 연결 방법 넣기
- 여러 시안이나 변형 만들기
- 구조적으로 결합되지 않는 부품
- 서로 맞지 않는 홈과 돌기
- 구멍 수와 핀 수가 다른 구조
- 중심 그림과 확대 그림의 방향 불일치
- 의미 없는 장식과 불필요한 공구
- 이미지 생성 모델이 만든 잘못된 한국어 문구

```text
- [도구 또는 연결 부품]

- [재료와 부품의 위치]

[연결 과정]
- [도구가 작동하는 방법]
- [부품이 이동하는 방향]
- 힘의 방향을 단순한 화살표로 표시한다.

[연결 후]
- [완성 상태]
- 부품 사이에 불필요한 틈이나 높이 차이가 없어야 한다.
- 실제로 결합 가능한 구조로 그린다.

[확대 단면]
- [확대해서 보여줄 부분]
- 본 그림과 부품의 색상, 모양, 방향과 위치를 일치시킨다.

[넣지 말아야 할 요소]
- [혼동될 수 있는 다른 연결 방법]
- 글자, 숫자, 제목, 로고와 워터마크

정사각형 게임 카드용 이미지 한 장만 생성하고
권장 파일명은 ‘[파일명].png’로 알려줘.
```

# 4. 나사못 이미지 예시

```text
앞서 정한 ‘연결하기’ 공통 스타일로
목재용 나사못 연결 이미지 한 장만 제작해줘.

밝은 갈색 목재판 두 장이 정확히 겹쳐 있다.
위쪽 목재에는 나사못 몸통보다 작은 예비 구멍이
목재 표면과 수직으로 뚫려 있다.

십자 홈이 있는 은회색 목재용 나사못 한 개를 사용한다.
십자드라이버 끝은 나사 머리의 홈과 정확히 맞아야 한다.

연결 전:
나사못 끝이 예비 구멍 입구에 수직으로 놓여 있다.

연결 과정:
드라이버가 나사못과 같은 중심축을 유지하며 회전한다.
나사산이 목재 섬유에 파고들어 대응 나사 홈을 만든다.

연결 후:
나사 머리가 위쪽 목재 표면과 평평하게 맞닿고,
나사산이 아래쪽 목재를 충분히 잡아
두 목재의 접촉면이 빈틈없이 밀착된다.
나사못 끝은 목재 바닥 밖으로 나오지 않는다.

확대 단면:
나사산이 아래 목재를 잡고
위쪽 목재를 아래 방향으로 당기는 구조를 보여준다.

못, 망치, 볼트와 너트, 리벳과 접착제는 넣지 않는다.
한글, 영문, 숫자, 제목과 로고를 넣지 않는다.
이미지 한 장만 생성한다.

권장 파일명: 나사못.png
```

# 13. 참고 이미지가 있을 때 사용하는 프롬프트

```text
첨부한 참고 이미지의 기하 구조를 그대로 사용해줘.

변경 가능한 것:
- 색상
- 윤곽선
- 배경
- 그림자
- 교과서형 벡터 스타일

변경하면 안 되는 것:
- 부품의 수
- 부품의 위치
- 홈과 돌기의 방향
- 구멍과 핀의 위치
- 결합 순서
- 연결 전과 연결 후 구조
- 확대 단면의 방향

참고 이미지의 잘못된 복사본이나 비슷한 구조를 새로 만들지 말고,
첨부 이미지의 구조를 직접 기준으로 사용해줘.
이미지 한 장만 생성해줘.
```

# 14. 기술 구조 수정 프롬프트

잘못 생성된 그림을 수정할 때 사용한다.

```text
기존 이미지에서 다음 구조만 수정해줘.

[잘못된 부분]
- [현재 그림의 오류]

[올바른 구조]
- [부품의 정확한 위치]
- [부품의 정확한 방향]
- [홈과 돌기의 치수 관계]
- [구멍과 핀의 정렬]
- [연결 후 상태]

[반드시 유지할 요소]
- 기존 색상
- 기존 배경
- 기존 선 굵기
- 기존 카메라 시점
- 기존 그림 스타일

[반드시 제거할 요소]
- [잘못된 구멍]
- [불필요한 부품]
- [기술적으로 맞지 않는 구조]

수정된 이미지 한 장만 생성해줘.
다른 시안과 다른 구조를 만들지 않는다.
```

# 15. 이미지 내부 글자를 넣지 않는 이유

게임 이미지 안에 직접 글자를 생성하면 다음 문제가 발생할 수 있다.

- 한글 철자 오류
- 글자 깨짐
- 작은 화면에서 글자 흐림
- 반응형 화면에서 크기 조절 불가
- 접근성 저하
- 다국어 지원 어려움

제목과 설명은 웹앱에서 HTML로 표시한다.

```tsx
<figure>
  <img
    src="/images/methods/나사못.png"
    alt="나사못으로 목재 두 장을 연결하는 과정"
  />
  <figcaption>나사못</figcaption>
</figure>
```

# 16. 파일명 규칙

## 권장 형식

- 공백 사용하지 않기
- 한글 또는 영문 중 한 가지 체계 사용
- 파일명에 버전이나 설명 문장 넣지 않기
- PNG 권장
- 같은 이미지의 수정본은 기존 파일을 교체

## 예시

```text
종이.png
목재.png
나사못.png
볼트와너트.png
인장력.png
목재작업실.png
흔들리는책상.png
연결성공.png
안전관리자.png
홈아이콘.png
```

# 17. 새로운 채팅에서 작업하는 순서

1. 이 `IMAGE.md` 파일을 새 채팅에 첨부한다.
2. 마스터 프롬프트를 먼저 전달한다.
3. 가장 마음에 드는 기존 이미지 1~3장을 참고 이미지로 첨부한다.
4. 첫 이미지 한 장만 요청한다.
5. 결과의 구조를 확인한다.
6. 구조가 맞으면 같은 스타일로 다음 이미지를 요청한다.
7. 오류가 있으면 기술 구조 수정 프롬프트를 사용한다.
8. 한 번에 여러 주제를 요청하지 않는다.

# 18. 가장 중요한 마지막 문장

각 이미지 요청의 마지막에 반드시 다음 문장을 붙인다.

```text
이 요청에서는 이미지 한 장만 생성한다.
다른 주제, 다른 시안, 여러 패널과 콜라주를 만들지 않는다.
```

# 19. 최종 확인 체크리스트

이미지를 저장하기 전에 확인한다.

- [ ] 요청한 주제 하나만 들어 있는가?
- [ ] 연결 대상과 부품의 위치가 정확한가?
- [ ] 홈과 돌기의 크기가 서로 맞는가?
- [ ] 구멍과 핀의 수와 위치가 일치하는가?
- [ ] 연결 전과 연결 후 구조가 논리적으로 이어지는가?
- [ ] 확대 단면이 본 그림과 같은 구조인가?
- [ ] 불필요한 도구가 들어 있지 않은가?
- [ ] 안전 장비가 필요한 경우 정확히 표현되었는가?
- [ ] 이미지 내부에 잘못된 글자가 없는가?
- [ ] 작은 게임 카드에서도 대상을 알아볼 수 있는가?
- [ ] 권장 파일명이 지정되었는가?
